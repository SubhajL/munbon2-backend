## 1.5 AMENDMENTS from the gpt-5.6-sol adversarial pass (2026-07-12)

`gate_configuration.json`) with one correction: `weekly_demand_calculator_v2_updated.py` is
a **method-patch fragment**, not a third runnable calculator.

**Re-scoped "ready-now" boundary:**
- **2.1 SPLIT (HIGH #1):** the สบ.1 sill/FSL sheet has **no M-id** — the canal/station join
  needs RID review like the crosswalk. Ready-now slice = generator/provenance/topology +
  geometry (fold 2.2 in); **sill/control-structure emission is GATED on an approved
  structure join; never emit default sills.**
- **NEW 2.6a (HIGH #9) — unblocked, do FIRST:** restore BFF boot (bff `main.py:19` imports a
  calculator referencing missing modules) + producer-ownership decision (the weekly
  implementation lives in **bff-water-planning**, not ros-gis-integration; the ros-gis
  client posts to the scheduler, not `/control/demands`). 2.6 proper stays RID-gated.
- **2.7 = offline pure-algorithm slice ONLY (HIGH #11):** the inverse needs real
  upstream/downstream levels + approved sill geometry; the wired service substitutes
  assumed heads/default geometry and Wave 4 admits telemetry is stale. `/control` wiring
  must require an explicit freshness-stamped boundary-condition set or answer
  "opening unavailable" — never an assumed command.
- **Wave 3 needs an ownership ADR before 3.1 (HIGH #13):** a standalone
  `services/scheduler` (optimizer, persistence, approval lifecycle, MILP/mock routes)
  already exists — don't create a second scheduler truth in flow-monitoring/core.
  Recommended split: hydraulic feasibility stays in flow-monitoring; greedy scheduling goes
  in the scheduler service with a retirement path for its current routes.

**Design amendments to fold into the PRs:**
- **Geometry model (HIGH #2):** 99 `Characteristics` subsegments don't fit
  one-record-per-edge (`conveyance_loss.py:80` overwrites duplicate edges;
  `canal_capacity.py:31` ignores segment Qmax) → each reach = ordered non-overlapping
  segment list; sum segment seepage; capacity = min(segment, gate); validate chainage
  coverage; multi-segment regression test.
- **Calibration schema before 2.3 (HIGH #3):** loader treats `has_calibration=true` as
  measured/0.95 and ignores K1/K2 when false → add explicit `calibration_method`,
  `source_gate_ids`, `confidence`, source version; measured/inferred/default stay distinct.
- **Release-bundle atomicity (MED #4):** startup can mix network/geometry/calibration files
  from different releases → release manifest with all artifact hashes + one release ID;
  promote atomically; startup rejects mixed releases.
- **2.5 versioning schema (HIGH #5):** `sections.section_id` as sole PK cannot express
  version+effective-date; global partial-unique `is_primary` would reject historical rows →
  dataset-version parent + composite keys, or immutable history + current views; constrain
  primary mappings per active dataset/effective interval.
- **Cross-DB ETL mechanics (MED #6):** no `db-migrate` exists and `.sql` is gitignored →
  content-addressed source snapshot → staging tables (transactional) → count/hash
  validation → atomic active-dataset pointer flip; name exact tracked
  migration/apply/rollback commands.
- **2.5b membership table (MED #7):** parcel→section is NOT 1:1 — effective-dated
  plot–section membership with intersection area/fraction + per-plot area conservation;
  quarantine only invalid/sliver/ambiguous geometry.
- **2.4 storage (HIGH #8):** mutable `weekly_water_demands` upsert overwrites prior
  calculations and can't hold interval allocations/delivery provenance → immutable
  versioned demand records, allocation intervals, delivery observations as SEPARATE
  stores; **m³/s = m³ ÷ scheduled-delivery-seconds** (not whole-period elapsed); explicit
  timezone, interval bounds, source, quality, idempotency keys.
- **Synthetic-data live path (HIGH #10):** `daily_demand_calculator.py:408/445/472`
  fabricates plots on ANY query failure even with mock mode off → remove
  fallback-to-mock outside an explicit test profile; dependency failure aborts the run;
  require non-synthetic lineage fields the receiving contract rejects by policy.
- **No silent clamp/quantization (HIGH #12):** return requested/achievable/deficit/reason
  per reach and **forward-recompute the full network after quantization**; below-floor
  demands → temporal pulsing/min-run scheduling, never a tiny continuous opening.
- **Scheduler run semantics (MED #14):** `Asia/Bangkok` + UTC instants, ISO year+week
  derived together, durable job-run table + advisory lock/idempotency, restart/misfire/
  backfill tests.
- **2.8 split (MED #15):** 2.8a generic feasibility fields (after 2.7-offline);
  2.8b data-lineage coverage (needs 2.2/2.3/2.5/2.4/2.6).
- **2.9 reframed (MED #16):** schema tests live in each API-changing PR; 2.9 becomes a real
  producer→flow-monitoring→Postgres→plan integration test AFTER 2.8.
- **Truthful health (MED #17):** both demand services report dependencies unconditionally
  healthy and fabricate `last_sync=now` → persisted run status, source/output version,
  freshness, accepted/rejected/quarantined counts, last error.

**Revised ready-now order:** 2.6a (boot+ownership, unblocked) → 2.1-split

## 6. Top risks to Wave-2 as a PRODUCTION pipeline
1. **RID approvals are the real critical path** — crosswalk renumbering, crop register, area
   authority. Code can be ready and still not production-acceptable without these.
2. **Cross-DB ETL** (`postgres.gis.zone` → `munbon_dev.ros_gis`) — two databases on one server;
   pick a repeatable, versioned, effective-dated sync, not a one-off copy.
3. **Id-vocabulary reconciliation** — `gis.zone` codes vs SCADA section numbers vs `ros_gis`
   `area_id` vs `M(i,j)` gates vs SCADA/PLC addresses. `core/node_id.py` handles the gate half;
   the section-code half needs an explicit, tested crosswalk.
4. **Synthetic-data contamination** — the 327 backfill rows and all-rice/1970 parcels must be
   quarantined/rejected, not silently recomputed over.
5. **No CI has executed** (E6) — every gate is local-only; a production data pipeline should
   not merge unverified by CI.
