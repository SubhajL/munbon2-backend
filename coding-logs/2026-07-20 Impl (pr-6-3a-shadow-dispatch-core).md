## Exactly-once & fail-closed (verified on real Postgres)
Integration (disposable postgres:14 on :55442, NEVER a real DB): migration 0010 applies + append-only (UPDATE/DELETE rejected); a full claim→dispatch→persist tick stores EXACTLY ONE receipt; a restart/retry re-run produces ZERO new rows (SCADA's idempotent replay + ON CONFLICT compose); `record_validation_receipt` twice → first True / second False, one row. Persist happens ONLY after a 200 body; a 503 persists nothing and the next tick re-dispatches. NEVER-execute is structural (single validate method, base-URL-embedded-path rejected, no actuate route reachable). Dark-by-default: no SCADA url / no secret / mode!=shadow → dispatches nothing.
